# Git 提交与 GitHub 同步

仅执行本次请求或已有约定授权的范围。“保存”不自动 commit/push；“提交”只完成本地提交；“同步到 GitHub”可以包含必要提交和推送，不要求重复确认。未指定远端时读取现有配置，多个目标不明确再询问。不能因使用本 skill 就创建远端仓库或改变可见性。

## 操作流程

1. 查看仓库状态、当前分支、远端与已有暂存内容。检查本次拟提交文件和差异；保留其他任务的修改。若无 Git 仓库，只有用户已要求初始化/建立版本管理时才初始化。
2. 提交时仅暂存本次相关文件，不默认 `git add .`。已有不相关暂存内容时采用限定路径提交等方式隔离；无法可靠隔离时说明阻碍，不偷偷混入提交。提交说明概括文献、Topic 或资料的实际变化。
3. 推送前核对目标远端与分支，获取远端状态并判断差异。同步有入站变更时先读取差异，在可安全合并的情况下集成后再推送；不强推、不丢弃本地修改，不自动 reset 或改写已有历史。
4. 合并冲突按证据处理，可确定的格式冲突可修复，冲突观点不得擅自选边。无法确定或认证失败时保留本地成果，报告未同步原因与剩余动作。不要在失败循环中反复重试。
5. 检查提交内容与推送结果，报告提交 ID、分支及远端状态。推送成功后核实远端分支包含该提交；仅 commit 成功不能称为 GitHub 已保存。

## 备份内容

普通图片可随笔记跟踪；避免无意义的重压缩、重复副本和缓存。遵从已有 `.gitignore`、`.gitattributes`，不提交凭据、临时文件或可重建索引。

生成式调研报告的完整保存还应覆盖源稿、正式数据、生成脚本、模板与依赖说明；按[报告文件与维护](survey-maintenance.md)核对未跟踪文件和忽略规则，不将只保存阅读成品等同于可维护备份。

默认推送 Markdown 笔记、必要图片和约定的模板；不自动纳入原始 PDF、临时论文下载和整份聊天导出。Git 本地提交提供版本记录，只有推送成功才报告远端已保存。不要把这一约定当作删除既有附件的指令。

用户明确要求保存大附件时再检查大小和仓库既有策略。若使用 Git LFS，不能把已提交指针当成附件已上传；检查实际对象可取得且上传成功后再报告完整同步。不要为加一个附件改写全库历史或启用付费服务。

具体限制以 [GitHub 大文件文档](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github) 和 [Git LFS 文档](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-git-large-file-storage) 为准，不在 skill 中固化价格与额度。

## 校验范围

提交前检查 frontmatter 能解析、ID 不重复、Topic 引用与相对链接能定位、图片存在且不是未下载的 LFS 指针。只检查本次影响范围及关联对象，不因笔记更新而运行无关的软件测试。尚无自动校验器时可直接检查，不声称已有校验脚本。
