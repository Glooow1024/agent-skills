# 用户工作流配置

这些是用户已提供的偏好；仓库位置与远端地址尚未指定。使用时核实实际资源，当前请求优先于默认配置。

## 当前环境

- 默认领域：具身智能。
- 浏览工具：Obsidian；知识库为本地 Markdown 文件夹，使用 Git 管理并推送云端，沿用此前 GitHub 方向，实际远端待配置。
- 精读讨论在豆包或其他对话模型完成，Agent 负责交接后的标准化、标签和知识库更新。普通总结、结构化交接材料与可访问的分享链接均可接收。
- 本地知识库根目录、GitHub 远端、分支和仓库可见性：尚未指定；不要把 skill 所在目录自动当作知识库。
- 宿主需具备本地文件读写能力；提交与同步另需 Git 和 GitHub 访问能力。无法操作文件时交付草稿并说明未保存。
- 默认文献模板：[Template-论文笔记.md](<E:/knowledge_base/embodied intelligence/基础文件/Template-论文笔记.md>)。生成笔记时读取该文件的当前内容；位置变化时更新此配置。无法读取时使用 skill 内的 [模板副本](../assets/paper-note-template.md) 并说明，副本不与原文件自动同步。
- 信息嗅探默认使用 `inbox/`，Topic 总结默认使用 `topics/`；已有仓库以实际结构为准。
- 默认“保存/入库”指写入本地文件；“提交”指 Git commit；“推送/同步到 GitHub”包括完成必要提交及推送。明确约定自动提交或推送后沿用，不重复确认。

## 用户偏好

- TL;DR 偏好：系统性技术先概括体系，再讲模块属性、职责及协作；单点技术先说明系统位置和角色，再讲痛点、核心思想、创新与效果；两类都突出独特想法、技术或观点。具体写法以 [SKILL.md 的 TL;DR 约定](../SKILL.md#tldr技术定位机制与独特贡献)为准。

- 不要求用户在 Agent 中重新讨论。材料充分时直接整理；关键信息不足时只补问影响结论的部分。
- Before Reading 是初步了解后的个人总结与疑问，最终笔记原样保留；无需把它解释为完全接触论文之前的想法。
- 笔记结构以指定模板为准：基础信息及标签引用块 → TL;DR 高亮块 → banner → Before Reading 高亮块（导读、问题）→ 六个正文章节。保留原有 HTML 高亮样式，正文允许按具体工作调整。
- 标签支持跨目录检索和主题梳理；目录表示主归属，跨主题关联优先用链接，避免复制多份笔记。
- 同一 Topic 的对比表和总体总结放在对应 Topic Markdown 文档：有则更新，没有则新建，保留人工内容和研究脉络。
- 推荐目标为“我还不了解的”前沿或经典工作，优先高质量发表渠道及扎实的一手研究，避免低价值凑数。
- 当前具身智能论文重点检查仿真/真机、机器人本体与任务、数据规模与来源、训练/评测划分、成功率统计口径、基线条件、泛化和失败案例；领域改变后调整这些关注项。
- 新闻可先整理进入信息嗅探，用户主动要求时再跨条目综合、比较与消化，不默认周期推送。
