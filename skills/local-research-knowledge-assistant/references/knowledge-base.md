# 本地归档与更新

## 确定目标

读取用户指定的知识库根目录、仓库指令和现有模板。用户未指定时可从当前项目上下文识别唯一明确的知识库；不能将 skill 目录或任意 Git 项目视为知识库。仍无法确定时询问路径，期间可以继续论文讨论或生成草稿。

沿用现有仓库组织；新库按 [仓库格式](repository-format.md)。仅在用户要求初始化时建立知识库目录，不因载入 skill 就创建空库。

## 写入步骤

1. **读取与查重**：查看工作区状态，按 DOI/arXiv ID、记录 ID 或规范化来源查找已有笔记，再以标题和年份辅助匹配。版本相关但内容不同的论文标明关系，不盲目覆盖。
2. **归属与关联**：先完成对正文内容和用户重点的理解，再复用或提炼 3–5 个标签并选择 Topic。每篇论文一份主笔记。用户要求“整理入库并更新知识库”时，继续读取相关旧综述和表格并增量合并，不在完成单篇后停下再次索要同范围确认；仅要求单篇时不自行重写其他内容。
3. **保存**：写入或局部更新 Markdown 与元信息，保留用户观点、讨论来源与核验范围。已有或容易取得的核心图保存为真实文件并用相对路径引用；缺图列为可选待补项，不要求提交原始 PDF。检查编辑期间目标有无新改动，发生冲突时先合并可确定部分。
4. **检查**：读取保存结果，核对 YAML、记录 ID、内部链接、图片文件和表格；检查差异只包含本次任务所需内容。对关键原图查看清晰度与裁切。
5. **交付**：报告文件路径与变更。明确目前是已保存、已提交还是已推送；需要 Git 操作时执行 [git-workflow.md](git-workflow.md)。

移动或改名后修复受影响的相对链接；删除图像前检查其他笔记引用。不要为整理一篇笔记而批量重命名全库，或覆盖尚未提交的用户改动。

## 后续补充

同一论文的新一轮讨论或改进总结更新同一记录，保留 Before Reading 原文与纠正脉络。关键结论仍不确定时保留待验证项，不因为笔记排版完成就改写为已核验。用户主动要求保存未完成讨论时才保存阅读检查点。
