# 调研报告的文件组织与维护

新报告进入展示与工程交付阶段时读取；整理已有报告的源文件、生成依赖或缓存时也适用。研究期间只需按调研流程保存源稿、正式记录和临时材料，不提前执行本文件的全部工程要求。单纯改文字或链接无需重整目录。沿用仓库约定，不为了套目录结构迁移现有文件。

## 先分清哪些文件由人维护

| 类别 | 内容与维护方式 |
|---|---|
| 源稿 | 综述、分析及人工说明，作为正文修改入口 |
| 正式数据与证据 | 稳定文献 ID、元数据、分类、机制依据、来源链接、必要摘录或定位信息、词云语料及规则；每个字段明确权威来源 |
| 生成工具 | 当前使用的脚本、模板、配置、依赖清单及必要字体或资源说明 |
| 阅读成品 | HTML、Markdown、图谱、图表、BibTeX 等，按读者需要交付，说明哪些可重新生成 |
| 临时材料 | 候选列表、抓取副本、下载与提取中间文件、运行日志、缓存和一次性修补脚本，集中存放，不作为隐含生成依赖 |

新报告可采用如下布局，只建立实际需要的目录；小报告可合并目录，但仍需区分角色：

```text
survey/
  src/          正文源稿
  data/         正式数据、证据记录和生成所需语料
  scripts/      构建、验证与打包入口
  templates/    页面与图表模板
  output/       可直接阅读和分发的成品
  .cache/       可清理的下载和中间文件
  .gitignore    版本管理的排除规则
  .site-publish.json  网站发布清单（网站支持此协议时由生成流程产出）
```

沿用研究阶段对临时材料的隔离，在交付阶段完善局部忽略规则，覆盖缓存、虚拟环境及可再生成的重复压缩包；不要用宽泛规则误排除生成所需的数据。`.gitignore` 只决定跟踪范围，不负责删除，也不能据此判定文件无用。

## 保持一套可维护的生成流程

- 正文在源稿中改，元数据和分类在正式数据中改，显示逻辑在模板或脚本中改，再统一生成成品。不得只改生成的 HTML 或 JSON，导致下次构建覆盖修正。
- 论文替换、链接修正和主题重编号直接进入正式输入。确需覆盖原始字段时，将覆盖值、原因与来源放在可见的数据或配置中，避免散落在多个脚本的硬编码条件里。
- 数量和统计从数据计算；格式约束与版本信息集中配置。内部路径相对项目定位，字体、运行时和外部依赖明确记录，不默默依赖某台机器或工作区外的文件。
- 当前构建流程不依赖旧候选数组、历史补丁或缓存。资料获取与报告渲染分开：保存足够的正式输入后，应能离线重建离线报告。
- 可复用的采集、校验能力有维护价值时合并进当前工具，读取正式输入并明确输出；网络发现结果先作为候选，核查后再更新正式记录，不凭页面可访问就覆盖论文归属。一次性补丁完成后，将结果并入正式输入或模板，不让维护者反复运行迁移脚本。

提供简短维护说明，沿用仓库的目录说明文件约定（如 ASUMMARY.md）。写清阅读入口、各项内容的修改入口、构建和验证命令、依赖与资源、输入输出关系、增删文献需同步的位置，以及哪些文件可清理。维护说明不混入报告正文，也不必加入读者下载包。

## 网站发布按需处理

仅在报告需要接入静态站时读取[网站发布约定](survey-publication.md)。未要求或未接入网站的报告无需准备发布清单；网站细节不占用研究与写作阶段的工作。

## 验证完整保存

首次交付或生成依赖变化后，用准备交付或入库的文件在独立临时目录重建一次，不复制缓存和历史中间文件。检查结构、链接、数量、图谱引用及必要交互资源；比较正文与分析数据是否与当前成品一致。图表时间戳、自动标识等可变信息不应冒充内容差异。仅运行语法检查不能证明生成依赖完整；局部文字修改无需反复执行整套重建。

用户要求完整保存或同步报告时，检查成品之外的源稿、正式数据、模板、脚本及依赖说明是否一并纳入授权范围。不要把“已跟踪文件没有改动”说成“维护材料已全部保存”：还需检查未跟踪文件及被忽略的必要输入。提交推送仍遵循[Git 操作](git-workflow.md)与用户已授权的范围，生成报告本身不自动授权提交。

## 清理前判断信息是否仍有价值

1. 查明文件的用途、调用关系和当前内容。以内容与实际依赖判断，不按文件名、是否被忽略或能否重新下载直接判定。
2. 核对旧脚本中的有效修正已进入正式输入；必要的可复用能力已整合，失效的编号、数组下标和旧版覆盖逻辑不带入当前流程。
3. 不参与构建的材料也可能是唯一证据、人工批注、不可重新获取的版本或未合并的判断。先保留这些内容及出处，再清理重复副本。自动截取的段落和运行日志不冒充已核验结论。
4. 在已授权的清理范围内，确认目标路径与仓库归属，保护无关文件；删除不必要的缓存和旧补丁，并检查正式输入及重建能力仍完整。无需为明确可丢弃的材料长期增加一个“备份堆”。
5. 若暂时采用可恢复隔离，明确隔离位置和是否仍占用空间，不称为已删除；实际删除后更新维护说明和忽略规则，移除过时的存放描述。文件组织、Git 跟踪、本地删除和远端同步分别据实报告。
