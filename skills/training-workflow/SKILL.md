# 模型训练工作流

用户于2026-10-31要求将本流程作为今后训练任务的默认做法。用户本次明确指令优先；不需要重复询问是否要看板、巡检、通知和收尾。缺少通知凭证或调度能力时完成其余工作，准确报告缺口，不声称功能已启用。

## 每次任务的交付

交付可追溯实验协议、经过验证的训练启动/恢复方式、可打开的实时看板、有限生命周期的监控及通知、训练完成的评估与归档。已有任务先修补缺项，保留原结果和有效服务；不为了套模板重建一切。短暂的冒烟/诊断训练可以挂在母实验下，不创建超过其生命周期的独立定时任务。

1. 读当前全局/项目/方法AGENTS与PROJECT_CONTEXT；核对本地及远端实际路径、Git状态、资源归属、依赖环境和现有实验。优先uv隔离环境。旧PID、端口、盘符、步数不是当前事实。
2. 先定问题、对照、变量和评估协议，再定训练预算与资源。把论文、发布代码、当前实现的差异逐项记录；起始权重、数据划分和实际采样都要有证据。改进版本独立编号，修复前后不拼成同一条无标注曲线。
3. 用小规模真实训练验证数值、数据覆盖、资源和完整断点恢复，再开始长训。启动成功不等于训练正常；要看到所有rank的更新与正确采样游标实际推进。
4. 提供看板与双层检查：默认每300秒由脚本检查运行异常，正常不调用模型；默认每3600秒由模型分析质量与收敛，正常或无有用新发现只留记录。间隔可以按单步、保存和评估耗时调整并记录理由。
5. 新异常先持久化、去重并直接通知，再触发固定聊天中的模型诊断。用户已要求的训练工作流包含在已授权任务内实施最小修复、验证并续训；不能借此改实验配方、操作无关资源或扩大消息接收范围。
6. 所有指定训练、依赖阶段及约定最终评估完成后，发送一次完成通知；确认回执后关闭本实验脚本巡检与模型周期任务，并验收停止状态。失败退出不等于完成，通知成功也不等于监控已停。

## 生成模板

```powershell
python -X utf8 C:/Users/Lenovo/.codex/skills/training-workflow/scripts/init_training.py --output <新实验文档目录> --run-id <唯一实验ID> --thread-id <本次已核实聊天ID>
```

生成`TRAINING_PLAN.md`、`protocol.json`、`MONITORING_ACCEPTANCE.md`、`HOURLY_REVIEW_PROMPT.md`、`INCIDENT_REPORT.md`、`FINAL_REPORT.md`。生成器只创建新目录，不启动训练、不注册定时任务、不发送消息、不读取凭证。可省略thread-id生成待填写草稿；真正部署前必须解析。模板是执行清单，不是通用训练/监控程序：按模型日志、调度系统和评估产物实现适配器，并做相关行为测试。

模板中的未知值用null/空列表/待填写保留；不能用NoPo4D旧GPU、20K、7片段28图、端口或聊天ID代填。模型指标按任务选择；图像重建才默认展示PSNR/SSIM/LPIPS及配对图像。

## 完成工作时向用户说明

先说当前结果与最重要限制，再给实验ID、看板入口、资源分配、最近推进和验证证据、消息渠道及停止条件。正常运行无需周期刷屏。若只有通知入队、仅接口返回成功、仅模拟测试通过或收尾尚待触发，要明确区别，不能写成已全部验收。
