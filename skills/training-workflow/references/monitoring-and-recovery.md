# 运行监控、恢复与收尾

## 先填写监控合同

为本任务确定实验集合、目标阶段/更新、最终评估范围、日志/产物适配器、GPU租约、聊天ID、通知目标、任务ID及停止操作。绑定稳定ID，不使用当前焦点窗口或“最后一个聊天”。同一实验复用现有任务，不能重复注册多个巡检。共享监控只有全部约定实验结束才关闭。

脚本频率默认300秒；模型质量检查默认3600秒。15分钟无推进仅是初始排查提示，依据近期正常单步、保存和评估时长校准，不能当作自动杀进程阈值。短任务采用随进程生命周期运行的检查或挂在母实验下，仍需日志和收尾。

## 两条检查路径独立

脚本用CPU与轻量文件/进程读取，正常不调用模型：退出/进程归属、各rank推进、NaN/Inf/OOM/NCCL/数据错误、游标连续性、检查点和评估队列、磁盘余量、阶段依赖、监控自身心跳。只扫新错误；第一次建立历史基线，避免旧故障重复报警。标注loading/saving/evaluating/waiting_resource/waiting_dependency，不能由低GPU利用率判死机。SSH连续失败是监控中断，不是训练已死。

模型每小时做质量判断；异常事件提前唤醒诊断。先验证实际支持的事件接口和聊天归属。`detected → persisted → queued → started → handled → verified`各状态分别记录；入队不是诊断成功，进程启动不是恢复成功。遇到聊天占用、接口缺失或权限限制，持久化等待并让小时检查兜底，向用户说明延迟。

模型检查还需监控脚本的心跳和消息outbox，不能只有训练被监控。若用户要求本机离线也通知，应把探针与通知部署到训练侧或独立运行节点并验收；本机Windows任务不具备这一能力。

## 最小事件记录与并发

事件至少保存run_id、stage、UTC时间及展示时区、故障类型/指纹、各rank步/游标、现场证据路径、已通知状态、修复次数和验证结果。凭证和原始敏感堆栈不放消息；报告用必要摘要和事件ID。报警去重按事件和阶段，状态稳定恢复后再复发应建立新事件。

单写者/文件锁防脚本重入；恢复采用独占租约，人工、异常任务与小时任务先检查谁在处理，不能并发重启。检查点用原子完成标记，评估期间pin住对应检查点，避免滚动保留删掉待评估权重。消息发送先持久化outbox，明确pending/sending/sent/failed；崩溃时sending属于回执不明，不盲目重发。接口无幂等支持时不能承诺绝不重复。

## 自动修复范围

1. 先保存故障日志、触发批次、原代码/配置、最近完整未污染的模型/优化器/调度/随机/采样状态。检查失败发生在更新前还是更新后，不把污染状态当续训点。
2. 优先重放最小故障批次、区分数值问题、数据/恢复问题、资源/进程问题。修复有证据的边界或运行错误，保留版本，针对性验证；数值稳定修复还要检查正常域是否改变。
3. 已授权任务内可以完成最小修复并续训；涉及新数据/目标、损失权重、LR课程、阶段起点/预算、广泛解冻、从头重训或处理无关任务时，遵守用户已有范围，缺授权才具体说明差异并询问。
4. 不用跳过异常梯度/样本、关闭保护或任意阈值削掉困难样本来假装恢复。不能仅按进程名杀任务。
5. 恢复必须核对所有rank更新推进、采样连续性、模型/优化器/梯度有限、冻结/LR正确、检查点和看板同步。确认后才通知恢复。同一故障默认最多两次有依据修复尝试；仍失败就保留现场、通知用户需要的决定，不盲目循环重启。

## 通知

用户于2026-11-01要求巡检启动时也通知：新实验注册并启用周期任务后，核实任务启用且首轮真实探针成功，再通过已授权渠道发送一次启用确认，包含范围、周期和本机离线限制。按实验持久化去重，不因每轮脚本进程启动而重复；补接已有实验时明确是补发确认。失败或完成收尾不发送正常启用消息，保存发送回执；不把消息入队当已送达。

优先复用用户已授权且适用于本任务的渠道；当前用户偏好飞书机器人。复用凭证引用而非复制密钥，核实接收群及内容范围。更换群/收件人、向团队广播或发送更多内容不由技能自动授权。若缺配置，准备本机私密配置并让用户填写，不索要聊天中的密码。

新异常由脚本直接通知，不等待模型；恢复、无法处理和全部完成再通知。正常不刷屏。首次接入发明确标注的测试消息，记录服务端回执与用户确认是否到达；服务端接受不代表手机已弹通知。网络失败有限重试，频率退避，失败由模型检查兜底。消息提醒与模型唤醒是独立链路，分别验收。

## 确定的结束条件

按本任务protocol的目标阶段与产物判定，不把NoPo4D的20K/7片段28图写死到新任务。至少交叉确认：

- 所有指定训练/依赖阶段正常完成，完整checkpoint落盘且身份/步数正确；所有rank到达目标或有框架明确的等价完成证据。
- 所有约定最终评估、指标、图像/输出及聚合结果存在且有效，最终checkpoint与评估输入对应；队列清空，无未解决评估错误或仍在运行的评估进程。
- 连续两次稳定观测或等价原子完成证据，避免保存/阶段切换竞态。字段缺失、读取失败或失败退出不能当完成。

顺序为`完成核验 → 一次完成通知成功 → 禁用脚本任务并验证 → 暂停模型周期任务并验证 → 保存停止回执`。停止监控不关闭供用户查看的面板，不删除结果。不能仅在提示词里写“结束后停止”却没有实现与验收。

如果脚本无法调用应用的暂停接口，可以在通知成功后立即停脚本，写持久化收尾标记；模型周期任务下一次触发先执行自停分支，不再质量检查。明确说明延迟及应用在线前提。优先用已支持的自动任务工具/API，不直接改私有调度数据库。通知失败/禁用失败/回执不明不得假报完成，保留可重试记录并升级。

独立测试结束链路时用隔离假数据、模拟通知和临时任务，不能给真实训练发虚假完成通知或提前停掉生产巡检。覆盖缺一个阶段、缺图/指标、旧评估、待排队、通知失败、暂停失败、进程崩溃和重复运行。
