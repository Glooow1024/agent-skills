# Knowledge Sync

本地知识库的 Windows 定时 Git 同步工具。使用 Python 标准库、现有 Git 和 Windows 任务计划程序；不调用 AI，不上传到额外服务，不需要常驻进程。

## 主力电脑

每天按北京时间运行，周末相同：

| 时间 | 操作 |
|---|---|
| 09:00、12:30、18:30 | 完整同步：检查稳定性 → fetch → 提交本地修改 → 合并远端 → 推送 |
| 登录、解锁 | 如果存在未处理问题，显示状态窗口 |

只处理已保存到磁盘的修改。首次发现一组改动后观察至少 15 分钟，再次检查内容及修改时间；期间有新变化则重新计时。延后检查使用一个复用的一次性任务，进程安排完即退出。首次发现的文件即使时间戳很旧，也会先观察，避免复制文件保留旧时间戳导致提前提交。

三个时间点使用同一个同步任务。fetch 只获取远端记录，不修改笔记；本地有稳定且符合规则的修改时先创建提交，再预检并合并远端，无冲突才推送。本地干净时直接检查合并；没有变化不创建空提交。等待稳定期间暂不合并远端。

电脑休眠时不唤醒；任务设置为恢复可用后补运行。使用当前用户的交互登录会话，不保存 Windows 登录密码，注销期间不运行。实际执行时间可能受休眠、登录状态和 Windows 调度延迟影响。

## 安装

需要 Windows、Python 3.11+（包含 Tkinter 与 pythonw.exe）、Git，以及已能在该用户环境下无交互访问目标远端的 SSH 配置。

在 PowerShell 中进入本目录运行（路径换成这台电脑的真实路径）：

```powershell
.\install.ps1 -Repository 'E:\knowledge_base' -Profile primary
```

安装会创建 `KnowledgeSync-knowledge-base-*` 任务和桌面上的 `Knowledge Sync` 快捷方式。机器路径、配置、暂停状态、日志和待处理问题保存在 `%USERPROFILE%\.knowledge-sync\knowledge-base\`，不会写入工具仓库或知识库。使用普通用户目录避免某些打包应用将 AppData 写入虚拟目录，导致任务计划程序看不到配置。可用 `-RuntimeRoot` 指定其他真实本地目录。安装不会自动修改 Git 身份、SSH 密钥、执行策略或 Windows 权限。

如果系统策略禁止脚本，或没有注册任务的权限，安装会报告错误；请按你的电脑管理规则处理，不需要关闭系统保护。

## 晚间、周末使用的第二台电脑

先在第二台电脑克隆知识库和这个工具仓库，并配置该电脑自己的 Git 身份及 SSH 访问。使用独立配置安装：

```powershell
.\install.ps1 -Repository 'D:\knowledge_base' -Profile secondary
```

此模式在登录、解锁后尝试拉取，每 30 分钟检查本地修改，连续 15 分钟没有变化后再提交推送；不使用主力电脑的三个时间点。仅在当前用户保持登录时运行，锁屏不等于注销。

换电脑前，尽量在状态窗口点击“重新同步”，等它显示“已同步”再关机。该按钮仍遵守 15 分钟稳定窗口。不要依赖关机瞬间推送：关机过程中网络和程序可能被提前终止。若需要立即提交尚未稳定的改动，请自己用 Git 提交推送。

两台电脑同时离线修改同一篇笔记仍可能冲突。完整同步会先提交稳定的本地修改，再尝试合并远端。有冲突时保留本地提交并提醒，不推送，也不在实际工作区制造未完成的合并；请人工解决后再同步。第二台电脑登录、解锁时的只拉取检查仍不会提交本地内容；如果远端有更新且本地未提交，会提示，随后由完整同步处理。

不要在两台电脑之间复制 `.git` 目录或同步工具运行状态，每台电脑使用自己的 clone 和本地配置。

## 自动提交边界

- 只在配置的仓库根目录、分支及原远端地址一致时操作；不强制推送、不 reset、不自动 stash。
- 已有暂存内容、冲突、rebase/merge 或 Git 锁时暂停，保留手动操作。
- 普通 Markdown、HTML 和常用附件可以提交；隐藏文件、说明文件 `AGENTS.md` / `SKILL.md`、未知类型需要人工处理。
- 发现删除/移动、超过 40 个改动文件、单文件超过 25 MiB 时暂停。上限可在本机配置调整。
- 检查变更笔记中显式的 Markdown、引用式、Obsidian 嵌入和 HTML 图片路径；资源必须是仓库内存在且会被 Git 收录的文件。使用文件名搜索的模糊 Obsidian 链接可能需要改成明确相对路径。本工具不是完整 Markdown 解析器，不验证外部网站或所有普通文章链接。
- 准备提交期间再次校验文件快照。使用独立临时 index 和 Git index 锁，不把其他手动暂存内容混进提交。
- 使用本机现有 Git 身份、hooks 和签名设置。如果它们需要交互，会报错或超时，由用户处理。
- 网络失败保留本地提交，在下个计划时间或点击“重新同步”时重试。推送过程中若另一台电脑抢先更新远端，会被 Git 拒绝，不覆盖远端。

## 提醒、暂停与记录

异常时打开一个独立状态窗口，窗口在任务栏保留。关闭窗口不会清除问题；下次登录或解锁后仍可看到。相同问题不会在每轮检查反复创建窗口。没有问题时不弹窗。

桌面快捷方式随时查看状态、重新同步、暂停或恢复。暂停不会清理改动；恢复后等待下一次计划检查或手动点击“重新同步”。运行日志达到约 1 MB 后轮换一次。

任务崩溃后进程互斥锁由系统释放；如果在 Git 提交关键步骤被强制结束，可能留下 `index.lock`，工具会提示人工检查，不自动删除锁。先确认没有 Git 进程和未完成操作，再处理恢复。

命令行只读检查（不 fetch、不提交、不推送）：

```powershell
python sync.py inspect --config "$env:USERPROFILE\.knowledge-sync\knowledge-base\config.json"
```

手动运行正常同步规则：

```powershell
python sync.py sync --config "$env:USERPROFILE\.knowledge-sync\knowledge-base\config.json"
```

卸载定时任务：

```powershell
.\uninstall.ps1
```

卸载保留配置、日志和快捷方式，便于查看和重新安装。

## 测试与资源

```powershell
python -m unittest -v test_sync.py
```

测试使用临时本地 bare 仓库，不访问真实知识库或 GitHub。涵盖快进、无冲突分支合并、冲突预检、暂存保护、编辑延后、图片缺失、提交期间继续编辑、推送失败恢复等情况。

空闲时无 worker 常驻。运行时主要成本是启动 Python/Git、检查文件状态、对本轮变化文件计算快照及网络传输；不会每次读取全部未变化图片，也不在本机执行网站构建。只在用户打开状态窗口或出现问题时保留 GUI 进程。

技术依据：[Git merge-tree](https://git-scm.com/docs/git-merge-tree) 用于不修改实际工作区的冲突预检；[Windows 任务设置](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset) 用于错过时间后的补运行。
